Q. Does the 60-minute timed run start once the raw data is already in HDFS, or should the copy from S3 into HDFS count towards the 60 minutes too?

A: Downloading the data, copying it from S3 to HDFS, and starting the cluster are excluded. The timed run covers processing the raw inputs through MapReduce, Hive, feature preparation, training and final outputs. Record the staging time separately.

Q. The brief also refers to an “assessed workload profile” and “issued runtime/storage settings”. Will these be released separately? We’re mainly asking about the EMR release version and EBS volume size, since those decide whether the GDELT data fits in HDFS.

A: For EMR, you may use emr-7.10.0.

Estimating your resource needs and justifying your choices is a useful part of the project. Nonetheless, I’m happy to provide a common reference configuration so you have a starting point:

- Cluster: one primary and two core m5.xlarge nodes; no task nodes or autoscaling
- Worker storage: one 200 GiB gp3 data volume per core node, with 3,000 IOPS and 125 MiB/s throughput
- HDFS replication: explicitly set to 2
- Spark starting allocation: two executors, each with two cores and 6 GiB heap memory

If you are unable to provision sufficient resources from AWS Academy credit, create a common AWS account and claim later within the allowed budget.

Tip 1: you should explain your storage and memory estimates, then compare the reference settings with a justified alternative using identical inputs and output checks. Report the median of three runs, resource use and any trade-offs. Marks will reward a sound comparison and supported reasoning; a faster run alone does not earn higher marks.

Tip 2: if the workload can't reasonably meet the 60-minute limit, identify the bottlenecks and an enhanced resource plan.

Q. Is Hive on Tez, the EMR default, acceptable for the Hive requirement?

A. Yes, Hive on Tez is acceptable. Use actual Hive execution and retain evidence of your queries and results. Spark SQL alone does not fulfil the Hive requirement, and the separate Hadoop Streaming requirement still applies. Tez is a supported Hive execution engine on EMR.

Q. The labs used Zeppelin. Is it fine if we build and export our notebook as a JupyterHub .ipynb on EMR?

A: Yes, JupyterHub on EMR is fine. The exported .ipynb is a required submission, regardless of which notebook interface you use. Include any helper files and setup instructions, and verify that the notebook reruns successfully in a fresh EMR session.

Q. For Task 3, can we have more than one model if we do more than one tasks?

A: Yes. As you are unlikely training a generative model, you should train one specialised model for each task. 

----

Q. For ML, can I have more than one approaches to solve one task?

A: Yes, you can have multiple approaches by training multiple models for the same task you choose. This is a good approach to demonstrate the technical depth and quality of your model.

Q: EMR limits the EBS root volume to 100 GiB. Is that enough for the project?

A: Yes. The root volume holds the operating system and applications; it is separate from the storage used for project data. 

For the reference configuration:

  • Set the root volume to 30 GiB per node.

  • Configure 200 GiB of additional EBS data storage per core node separately, under the core-node storage settings.
